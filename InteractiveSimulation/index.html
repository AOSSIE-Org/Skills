AOSSIE Skills Ecosystem Simulator Guide

Welcome! This simulator exists because the ecosystem's own docs had drifted from its code — new contributors couldn't tell what was actually running versus aspirational. Everything here was verified against the real source of SkillBot, PullRequestDashboard, and the Skills Core (AOSSIE-Org/Skills) repos.

Two things are explicitly separate here: what's live, running code today (the two scenarios you can trigger, and the Per-Repo Context / Skills Core / SkillBot / PR Dashboard cards), versus what's planned but not yet built (the Skill Updater's clustering-and-auto-PR pipeline — clearly marked ROADMAP).

Core Architecture

Per-Repository Context

AGENTS.md is a task-intent router in each project repo — it points to only the .agent/core, .agent/instructions, and .agent/info files relevant to the current request, instead of loading everything at once.

Skills Core (org-wide)

Skills live once in AOSSIE-Org/Skills as SKILL.md files (Claude-Code-style skills, with references/ for on-demand detail). SkillBot/scripts/sync_org_skills.py is the real, code-backed way they reach each project's org-wide-skills/ folder.

What's Actually Running

Skill Bot: keyword-matches the message to a repo (LLM classifier as fallback only), concatenates that repo's context in a fixed priority order, and unconditionally calls Ollama (llama3.2). It logs a gap to gap_log.json only on specific failure reasons — repo_clarification_needed, no_repo_context, ollama_unavailable, processing_error, thread_creation_failed — never on a confidence/quality judgment, because none exists.
PR Dashboard: a CLI script (main.py) that fetches PRs via gh, embeds them with sentence-transformers, clusters by cosine similarity, asks Ollama to explain each cluster afterward, and writes static HTML. It currently runs against closed PRs on a single hardcoded demo repo, and its skill-context loader currently no-ops (see "Docs vs Code").
Skill Updater: described in the org README as a BERTopic-based knowledge-evolution pipeline. Not integrated anywhere in this org's active codebase — gap_log.json is a real, growing file that nothing currently reads.

Docs vs Code — Verified Gaps

Each item below was confirmed by reading the actual source, not by re-reading the README. These are honest, current gaps — several are good first contributions if you want to help close them.

SkillBot's own README says context comes from AGENTS.md; the code (repo_router.py) actually reads .agent/core|info|instructions/*.md and skills/**/SKILL.md — it never reads AGENTS.md itself.
PR Dashboard's scripts/update_subtrees.py syncs skill files into SocialShareButton, OrgExplorer, GSoC-Proposal-Assistant, and Template-Repo — not into MiniChain, the repo github.py actually fetches PRs for. Context injection for the analyzed repo currently has nothing to load.
PR Dashboard's context.py globs repos/<repo>/**/*.md for skill context, but the repos/ directory doesn't exist in a fresh checkout — this step silently no-ops rather than erroring.
dashboard.py at the PR Dashboard repo root is legacy/dead code (an earlier monolithic version, hardcoded to a different model). Nothing imports it — main.py + github.py + grouping.py + ollama.py + render.py is the real pipeline.
PR Dashboard currently fetches state=closed PRs for a hardcoded repo (test/demo mode) — not the live open-PR triage the README describes.
The "Skill Updater" (BERTopic clustering, auto-PR patches) doesn't exist as integrated code in either SkillBot or PR Dashboard — it's a separate, external, not-yet-wired-in repo.
The Skills Core repo's own root CONTRIBUTING.md is still generic, unfilled Template-Repo boilerplate — confirmed by the repo's own AGENTS.md, which flags it.
Neither SkillBot's gap-fallback nor PR Dashboard's duplicate/conflict split uses any learned or adaptive threshold — just two fixed numeric cutoffs (cosine ≥ 0.55 for clustering, avg similarity > 0.75 for "duplicate").
